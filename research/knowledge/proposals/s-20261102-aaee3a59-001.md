# V5 P1 proposal — never silently fork training lineage

Main's existing weekly training workflow has a specific source-confirmed failure mode: a missing/expired or failed-to-download successful-run Artifact caused it to delete the expected pair and silently reinitialize MaskablePPO. This is not a verified continuation.

Proposed integrated fix on own PR:
- First verify prior Artifact with an explicit model SHA256, ZIP optimizer entry/CRC and pinned engine metadata; otherwise download both assets from the canonical registered latest unpromoted Release and byte-verify against the existing Release asset inventory.
- Fail closed if all sources are unavailable or incompatible. Random fresh initialization must be an explicit manual choice.
- Never overwrite the input checkpoint during output save; carry source/child SHA256 lineage and require independent real model canary.
- Fresh per-run evaluation seeds reduce repeated tuning leakage, but a proper final promotion gate still needs independent seat rotation and uncertainty.
- The 1408-step V5 release remains an unpromoted experimental checkpoint (heldout ranks [8,8,8]); 'latest' != Champion.
