# Proposal — treat latest postmerge main CI as an exact-SHA evidence claim

Scope: V7 `integrate/postmerge-exact-main-ci-evidence`, branch `agent/s-20261103-6a65ff77/optimization-001`, base main `3a745c6f6a48c65528bcbeb81b8627b8db93f046`.

An integrator cannot conclude an accepted merge was fully integrated based only on a green PR-head CI, a green run on an earlier main SHA, or an in-progress run. Audit the currently observed main SHA against a completed successful main **push** of the canonical `CI - full-match gate`; require its exact full-match job, successful tests/engine/real-game steps and a nonempty unexpired CI receipt Artifact. Then inspect the actual receipt JSON separately before claiming proven game facts.

The new checker `scripts/v7_main_ci_verify.py` intentionally returns `blocked` for main drift, failed/skipped steps, missing run/jobs, expired receipts and non-push CI. It is not an integration lock, merge API or policy-strength gate. A successful baseline CI cannot demonstrate raw PPO competence. This is a proposed verification improvement, not established on main until approved/merged and rerun against its exact new main SHA.

Source: https://github.com/sstxww/reinforcement-learning/actions/runs/41510861696 is confirmed successful on former main `c5edec2e...`; the newer `3a745c6f...` run https://github.com/sstxww/reinforcement-learning/actions/runs/41511419671 was in progress at first read. It must be rechecked; do not permanently label it failed or successful based on a snapshot. Experiments, new training steps, model releases, champion promotions: none from this audit.
