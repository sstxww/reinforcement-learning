# Proposed V5 knowledge — strict eight-seat receipt integrity

**Status: proposed for integration; this is an engineering correctness check, not a model win.**

Main `tavern_ai.validate_receipt.validate` originally accepted any eight integers between 1 and 8, without requiring each position once. `canary.run`, `scripts/check_pr_evidence.py` and `python -m tavern_ai.validate_receipt` use this base validator; a duplicated placement vector could pass those entrypoints. There is an existing stricter auxiliary `receipt_integrity.validate_integrity`, but it is not the gate currently invoked by the common CLI.

Proposed minimal fix: make the base validator require `sorted(placements)==list(range(1,9))`. Regression tests reject duplicate all-eight arrays, repeated rank 1, and boolean rank values, while accepting a legitimate non-ordered permutation.

The proposal prevents a class of malformed results from being accepted. It does **not** authenticate a file as generated by the actual engine by itself; require a real pinned-engine workflow and independently committed receipt, plus CI.

Separate research signal (not causal proof): unpromoted V2 PPO evidence in draft PR [#103](https://github.com/sstxww/reinforcement-learning/pull/103) measured 521 legally purchasable decision exposures but zero buys across 3 guarded full games. Draft PR [#107](https://github.com/sstxww/reinforcement-learning/pull/107) shows that forcing 46 buys did not fix rank eight in 3 new games. Study Play↔Cancel no-progress loops and guard dependence before scaling PPO. Do not promote those models.
