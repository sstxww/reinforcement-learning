# Proposed V5 integration: fail-closed Release recovery gate

## Verified from main source
The current `tavern_ai.train.run` checks `engine` metadata before calling `MaskablePPO.load`, but does not independently verify checkpoint bytes against a trusted SHA256. The shared weekly workflow finds the last successful Actions Artifact with finite retention, rather than using a durable immutable model registry.

## Isolated improvement
A minimal read-only registry manifest and recovery audit are implemented in this session's own paths. The verifier checks Release bytes + metadata, engine source/shape, learned step count, policy spaces, and optimizer state before allowing a bounded 128-step continuation attempt.

## Guardrails
- No automatic Champion selection; historic V2 model has held-out rank 8 evidence, not strength.
- Actual recovery, games and metrics require a successful real Actions execution. Do not infer those from unit tests or Release listing.
- Failed matches/recovery stop the workflow. No fallback model is substituted and labeled as PPO.
- Keep main-only training untouched until integration review establishes a durable source-of-truth registry and rollback policy.
