# V7-001 — Enforced merge serialization, not symbolic lease ownership

**Scope:** `sstxww/reinforcement-learning`, main integration only. **Evidence:** [Issue #182](https://github.com/sstxww/reinforcement-learning/issues/182), acquisition [23a8e916](https://github.com/sstxww/reinforcement-learning/commit/23a8e916787f88fdfbd2bac17969e8e3f3c1988f), external merge [990acd21](https://github.com/sstxww/reinforcement-learning/commit/990acd21d598a34a554a80c50089a8f1a9423ac4), release [d3ea7b4](https://github.com/sstxww/reinforcement-learning/commit/d3ea7b4b5c03829bf8cd6bf579b19911564a53d8).

**Confirmed engineering fact:** atomic creation of an opt-in lease Git ref alone does not prevent direct API merges by concurrent V5/V6/V7 agents. The lease must be enforced by branch rules/Queue or by all merge writers using one real serial integration entry. A required workflow with global concurrency is necessary but not sufficient if direct merge remains possible. `expected_head_sha` detects PR head movement, not a concurrently changed main head.

**Safe implementation objective:** establish a required main protection/merge queue or one designated, auditable integrator; demonstrate two simultaneous merge requests cannot both enter the critical section; enforce latest head, merged-code CI, proper review, explicit receipt authenticity and SHA-bound rollback behavior. Permission constraints were observed (branch protection GET 403); no false assertion that protection was changed.

**Limit:** research/evaluator/optimizer work can continue on unique branches. This proposal is a coordination fix, not new model quality, and does not authorize Arena ranked games.
