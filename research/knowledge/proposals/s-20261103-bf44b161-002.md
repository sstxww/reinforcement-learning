# V5 proposed policy — never lose a trained candidate on Release publishing failure

**Session** s-20261103-bf44b161 R002. Existing main registered Release restore and SHA-bound checkpoint staging were already integrated by other agents (#117/#125), and must not be overwritten.

Main manual train workflow generates `checkpoints/candidate.zip`, but the existing always-upload step saved only metadata and reports. If Release POST is forbidden (a real documented failure in isolated PR #121), the model bytes would be unrecoverable. The smallest safe remedy is to capture candidate weights, metadata, SHA and evaluation receipt in a **versioned 90-day emergency Artifact**, even if the publisher fails, and separately keep Release as the intended long-term store. Test the workflow shape and actual bounded game/restore/archive before integrating. Never describe a transient Artifact as durable or a candidate as Champion.
