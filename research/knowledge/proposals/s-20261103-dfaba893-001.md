# V7 P1 knowledge proposal: rollback ownership is not check-then-unlink atomic

**Status:** proposed/unmerged reviewer finding; session s-20261103-dfaba893, R001. Does not change canonical production restore.

A concurrent writer can replace the destination between `Path.samefile(stage)` and `Path.unlink()`. Exclusive `os.link` prevents a second linked install from clobbering but does not make this subsequent rollback deletion safe against legacy rename/replace writers. Ordinary tests that replace before the identity check miss the dangerous interleaving.

**Evidence:** deterministic synthetic counterexample in `reports/s-20261103-dfaba893/rollback-toctou-reproducer.py`, and GitHub PR #175 source code plus posted review https://github.com/sstxww/reinforcement-learning/pull/175#issuecomment-6586804588 .

**Safer criterion:** in any failure path, never delete a checkpoint that could belong to another writer. Where atomic conditional unlink is unavailable, prefer preserving a detectable orphan for explicit fail-closed recovery or use a truly enforced common transaction protocol. Two independently named files are not crash-atomic merely because each individual hardlink is exclusive. Add an injected post-stat/pre-unlink race regression before claiming no deletion.

**Limitations:** local interleaving establishes possible failure, not observed occurrence in TavernGym GitHub Actions. Not model evaluation. No PPO steps, no new model, no policy promotion.
