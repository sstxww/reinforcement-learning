# P0 proposal — fail closed on stale green main CI

The concurrent V7 workflow needs a check which does not confuse historical success with the exact current main. At session start main c1b828734527bae6141805581693d890cc3bff94 had run 41512315964 still in progress, while prior SHA 990acd21 had run 41511814464 successful.

This isolated implementation (scripts/v7_main_ci_gate_f6c9fea8.py) reads public main and workflow run metadata without mutating GitHub. It requires a push-triggered successful workflow on precisely the current main SHA and success of the test, engine, contract, and real eight-seat canary job steps. It refetches main after reading jobs and rejects a moving branch. All failures exit nonzero. A successful return is ONLY a CI precheck, not match receipt authentication, exclusive lease or permission to merge. Unit tests use synthetic run JSON, explicitly not game evidence.

No actual PPO training, persistent model, promotion, game performance or ranked Arena outcome is claimed by this gate. Integrator must still independently review the PR head, branch protections, actual real-game receipt, latest PR CI, and valid serialized merge ownership, then validate post-merge main again.
