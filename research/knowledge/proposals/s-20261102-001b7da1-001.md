# Proposal 001 — fail-closed checkpoint resume before adding PPO budget

**Evidence:** `tavern_ai/train.py` previously saved the model directly at the final path and checked only engine metadata on resume. Partial serialization could overwrite an existing good checkpoint; a corrupted ZIP with unchanged metadata was not checksum-checked before deserialization.

**Minimal fix:** stage the ZIP, hash its bytes into metadata, replace only after successful serialization, verify the bound digest and total step count on resume, and always close the engine environment. Local offline tests: 5 pass. See this session's separate PR and pending full-match CI for integrated verification.

**Limits:** legacy metadata lacks embedded SHA; use trusted model registry + Release asset preflight before loading. There is not yet a transactional ZIP+metadata pointer, a permanent checkpoint publication guarantee, or a new competitive model. Do not claim Champion improvement from this engineering change.

**Follow-on test:** an isolated, budget-bounded Release resume should fetch both assets, compare SHA against immutable registry, load+continue PPO 128 steps, preserve optimizer state, complete a pure-model match without guard, then publish and re-download a versioned model only if gates succeed. Existing V2/V5 behavior data shows buy suppression and hero-power/cancel loops, so diagnose before scaling.
