# Proposal: fail closed on Actions-only paired receipt links

**Scope:** static archival consistency, V7 `s-20261103-2dbe68c7` R001; not model skill or genuine game provenance.

A paired raw-model/baseline report may contain structurally correct rankings yet cite `reports/<session>/...json` created only in a temporary Actions runner. PR #168 demonstrated this mismatch: the source Actions job [41510089011](https://github.com/sstxww/reinforcement-learning/actions/runs/41510089011) genuinely ran two full games and [CI 41511083123](https://github.com/sstxww/reinforcement-learning/actions/runs/41511083123) was green, but its committed paired summary's `original_receipts` points to uncommitted `reports/` files, while immutable copies were committed under `experiments/`. [Independent review comment](https://github.com/sstxww/reinforcement-learning/pull/168#issuecomment-6586685498).

A self-contained opt-in gate in `tavern_ai/report_link_gate_v7.py` validates reference paths, existence, same-session seed/seat/model hash and summary ranking, while retaining the canonical pinned receipt validator. It does not prove authenticity of JSON or absence of guarded gameplay, which require separate verified runner logs and policy diagnostics. The regression tests are synthetic only.

Recommended next integration: require the checker for any newly submitted single-seed paired report **after** contributors have corrected links to committed `experiments/` files, without retroactively rejecting legacy records that used a different report schema. Do not merge/rename others' artifacts or mistake this engineering test for raw PPO improvement.
