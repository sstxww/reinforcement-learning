# V7 knowledge proposal: green step names are not immutable full-game evidence

**Version applicability:** current `main` near `c1b828734527bae6141805581693d890cc3bff94`, PR #185 HEAD `58073fd1157e84769e9f47bdead39584191216c4`; always recheck both hashes.

**Verified from source:** #185's proposed `check_jobs()` checks job conclusion and the five expected step names, not receipt bytes nor the trustworthiness of the workflow source. A PR can modify `.github/workflows/ci.yml` yet retain step names. This is a trust-boundary gap, **not proof that games were forged in any actual run**. Review evidence: https://github.com/sstxww/reinforcement-learning/pull/185#issuecomment-6586822516.

**Engineering proposal:** fail closed when PR changes the trusted CI/receipt/engine source paths, bind complete GitHub changed-files pagination to exact PR head/main, and independently validate the exact-run original game artifact before treating its green workflow as genuine game evidence. The new standalone checker covers the first conservative guard only; CI trust must additionally be established via trusted main execution or protected workflow controls. It does not authorize merge.

**Synthetic falsification test:** all expected CI step labels can be marked success even with a modified CI YAML. If any trusted proof path changes, the checker rejects it. Synthetic test inputs are never stored as real eight-seat receipts.
