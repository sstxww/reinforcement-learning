## Verified gap and minimal integration

Current main `tavern_ai.checkpoint_writer.verify_resume_digest` returns false if metadata lacks `checkpoint_sha256`; the canonical `train.run` had discarded this signal and loaded SHA-less legacy archives anyway. Under V5 P1, a continuation must be traceable to trusted checkpoint identity. A small wrapper makes that default fail-closed, preserving normal SHA-bound continuation behavior. This complements the already merged atomic checkpoint writer and #116 strict archive preflight; it does not fork a second model registry.

## Limitations and merge gates

The presence of a self-reported sidecar hash is not sufficient to establish Release provenance. The launcher must separately verify trusted registry hash, model ZIP/optimizer and engine metadata. Old SHA-less legacy weights require a deliberately audited migration using an external trusted hash before resuming; do not silently delete them or assert they are unusable for historical inference. Await exact-head CI and genuine own eight-player game receipt. Do not promote an unproved candidate.
