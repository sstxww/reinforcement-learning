# V7 proposal: immutable candidate saves must fail closed on path collision

Owner s-20261103-822bc450; Round 001; independent task checkpoint/candidate-save-no-clobber. **Proposal, not curated knowledge, until integrated.**

Main's checkpoint writer once staged weight/metadata bytes and then used os.replace() on the final names. A raced writer could replace an already published candidate, and an exception between two replacements could leave mismatched files. The distinct restore path is addressed by active PR #175; no edits to that path here.

This branch introduces os.link() no-clobber creation for the newly trained candidate and conditional rollback on ordinary second-file failures. Staged/final files share a directory; failures preserve old evidence. The pair is not power-loss atomic: a crash may still leave one file and safely block future overwrite. Tests inject collisions and second-file failures; they do not test distributed filesystems or prove model strength.

No PPO training steps, independent held-out comparison, permanent Release or Champion change have been performed by this branch. Complete real baseline game and Actions evidence will be added only after authentic run completion. V5 rank-eight remains a separate strategic problem, not solved by storage hardening.
