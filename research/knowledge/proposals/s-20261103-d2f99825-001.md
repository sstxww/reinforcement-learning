# V7 proposal: recover the exact seed from failing raw model evaluations

**Validated engineering diagnosis:** The main `tavern_ai.evaluate.evaluate()` computes a bulk candidate list before writing its aggregate JSON. If an intermediate raw game throws `RuntimeError: Full-game safety limit exceeded`, that call emits no per-seed report. In #165, Action 41509707315 ran a real Release-resumed 1536-step candidate; its full-game rank-8 smoke succeeded but its held-out aggregate failed and the specific seed was not preserved.

**Independent bounded remedy:** `scripts/v7_seed_isolation_d2f99825.py` uses official `canary.run` unchanged for each attempt, writes a strict full-game JSON immediately on success, and writes a distinctly named failure JSON on exception. It runs the matched baseline even if the model arm fails. Its summary contains no invented ranks and labels only completed pairs. Eight synthetic regression tests passed locally; real Actions evidence must be verified separately.

**Not established:** Root cause of no-BUY or no-progress; model performance improvement; checkpoint durability; failed game's rank; any approved merge. A single baseline smoke is infrastructure verification, not raw PPO improvement.

**Safe follow-up:** Once PR CI passes and integrator validates the code and receipt, select an immutable Release checkpoint, run a single predeclared known-failure seed pair in a bounded isolated runner, and inspect precise action-family transitions. Leave Best/Champion unchanged.
