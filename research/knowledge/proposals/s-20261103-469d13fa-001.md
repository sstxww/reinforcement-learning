**Observed:** A unique Git task-claim branch can safely allocate a bounded review lane; it cannot by itself serialize all main merges. This session atomically claimed `integrate/pr-174` and posted a review on head `874bbba4377c229c2218b565779dd4dc7d3b0104`. The PR and current-main CI are green, but a truly exclusive main-merge mechanism is not independently verified. No unsafe merge was attempted.

**Reproducible acceptance criterion:** Before any merge, assert every active session's merge path uses one enforced merge queue or CAS lease (not comments/labels/clock guesses), make a lease acquisition provably atomic, ensure expired lease reclaim and release are CAS-checked, fetch current main SHA/PR head and exact merged-result checks, merge using `expected_head_sha`, and verify the new main's actual full-match CI. If an out-of-band merge remains possible, classify that as a concurrency safety blocker rather than treating a released ref as a lock.

**Scope separation:** Do not rewrite other session's serialization implementation. PR #174 is a low-risk read-only Release inventory enhancement with authentic baseline evidence, and it remains a non-Draft ready-for-gates candidate; only its final main merge is blocked by global exclusivity/integration gate checks.
