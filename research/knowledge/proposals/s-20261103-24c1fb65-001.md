# Active model checkpoint SHA must match all model evaluation receipts

PR: https://github.com/sstxww/reinforcement-learning/pull/226
**Confirmed source-level gap:** a batch of internally consistent 64-hex model hashes was accepted by the main evaluator even if none identified the requested checkpoint path. This integrity gap is not evidence that historical real games were falsified.
**Proposed change:** SHA256 the active checkpoint before and after evaluation, reject any local mutation and all receipts not referring to those exact bytes. Keep raw, assisted, baseline, and candidate provenance separate.
**Synthetic regression evidence:** 16/16 target tests (including 3 new models) passed on the original branch run: https://github.com/sstxww/reinforcement-learning/actions/runs/41513100032 .
**Genuine engine evidence:** independent full-eight-seat baseline seed 97551 rank 6, 14 turns, 54 decisions, receipt asset SHA256 `980e417f24d935066e1db52f0810f2c9f1c0f511c5cca4f2d196dc75f075630a`, linked artifact 13173642844. Not PPO strength.
**Overlap:** Draft #148 independently proposes a pre-run model SHA check in a broader evaluator rewrite. Our post-run mutation guard is extra; avoid indiscriminate dual merging. Any model performance claim still requires raw-model full matches and held-out comparisons. No new weights or promotion.
