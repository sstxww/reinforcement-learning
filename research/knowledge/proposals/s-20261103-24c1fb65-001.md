# Proposed invariant: match every evaluation receipt to its requested checkpoint
SESSION_ID: `s-20261103-24c1fb65` | round 001 | source main `c1b828734527bae6141805581693d890cc3bff94`.
**Claim**: Existing evaluation verified hashes were consistent within a model batch but did not compare them with the checkpoint path passed to the evaluator. Code review on the stated base, not a statistical model finding.
**Patch**: SHA256 of local checkpoint before and after batch; all model receipts must reference the identical digest. Fail closed if file changes or mismatches. Baseline evaluation has no checkpoint.
**Tests**: three explicitly synthetic monkeypatched cases; a real eight-seat *baseline* workflow is separately proposed as infrastructure acceptance and cannot validate model quality. No raw model eval or PPO training claimed.
**Existing work**: #153 merged strict receipt validation; this patch tightens the remaining active-model identity link, subject to reviewer verification and duplicate-PR audit.
**Caveat**: this cannot prove a receipt actually came from a live engine without full-game evidence and trusted runner; it only closes one provenance consistency hole.
