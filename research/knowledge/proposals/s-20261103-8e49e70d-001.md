# V7 proposal: prevent unscoped session workflow amplification

**Status:** implementation and local synthetic regression evidence, live GitHub Actions outcome pending as of first commit. Session `s-20261103-8e49e70d`, TASK_KEY `ops/session-workflow-trigger-scope`.

Session-specific Actions workflows that expose an unfiltered `pull_request` trigger may run for *every unrelated PR* targeting main, even if the workflow also has `push.branches` limited to its own agent branch. In GitHub Actions, pull_request branch filters refer to the base branch; this is a scheduling/cost risk under 10–20 parallel sessions, **not** proof of a measured financial expense.

A new stdlib read-only audit `scripts/v7_workflow_trigger_scope_8e49e70d.py` conservatively scans session-identified filenames for broad event triggers, flags the exact workflow paths without editing others, and supports machine-readable JSON report plus optional fail-closed `--strict`. Six synthetic tests passed locally after fixing inline-YAML token detection. Each session should prefer `push` restricted to its own branch + own file `paths` and a bounded workflow; unrelated `pull_request` events should not be needed when canonical `ci.yml` performs the required PR gate.

This proposal makes no model-strength or optimizer claim. The registered 1408-step experimental model remains unpromoted and historically ranks eighth. Only after verifying full-match Actions and independent review should this become shared knowledge. No globally exclusive main merge right was acquired.
