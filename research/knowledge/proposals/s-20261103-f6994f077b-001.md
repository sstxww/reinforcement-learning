## Source-grounded defect

The existing `tavern_ai.seat_rotation.play` records both `seat` and `agent_placement=placements[seat]`. The canonical `tavern_ai.receipt_integrity.validate_integrity` formerly checked a valid eight-rank permutation but **did not cross-check these two fields**. Thus a JSON object claiming controlled seat 3 and rank 1 could pass integrity while the underlying `placements[3]` was rank 8. This is an integrity gap, **not proof that any actual archived receipt was forged**.

## Minimal repair

- Validate explicit `seat` as a real integer in 0..7; disallow bool, strings and negative/overflow indexes.
- For any supplied `agent_placement`, require a true integer equal to `placements[seat]`.
- Require explicit `agent_placement` for rotated nonzero seats.
- Preserve old honest seat-zero canonical receipts with no optional seat fields.
- Test synthetic negative mutations separately; fixtures are **not real games**.
