# Integration proposal s-20261102-847b6d4e-001 — reuse existing strict preflight, do not fork a second model registry

**Verified repo observations at start:** Main had canonical `models/registry.json` with 5 candidates (latest 1408-step unpromoted; Best/Champion null), `models/release_asset_digests.json` with both model and metadata SHA256 values, and `tavern_ai/checkpoint_preflight.py` that validates PPO ZIP, optimizer member and schema-2 metadata.

**Safety gap found:** `tavern_ai.release_asset_verifier.verify_local` checked both digests and metadata fields but could report success for non-ZIP bytes if both expected digests were consistently poisoned. Existing unit test used plain synthetic bytes and documented this weaker semantics. PR #93 proposes another verifier with a hardcoded four-candidate test, already out of sync with main; avoid duplicate tools.

**Targeted correction in this branch:** Make the existing public Release verifier call the existing strict archive preflight. Add synthetic tests proving matching hashes alone do not pass a broken PPO ZIP, missing optimizer state or unsupported schema. Distinguish file-level verification from real model load, optimizer resume, full game, and strength claim.

**Evidence gates:** Branch CI plus genuine full TavernGym eight-seat canary required before merge. No model performance change, no trained weights, no Arena ranked matches, no Champion promotion. A registry entry or GitHub API digest is not a byte-download or model-restoration proof.
