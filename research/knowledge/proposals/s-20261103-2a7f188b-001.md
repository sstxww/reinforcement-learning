# Proposal: audit PR game source-commit reachability (V7)

**Scope / status:** standalone optional tool `scripts/v7_receipt_ancestry_2a7f188b.py`, session s-20261103-2a7f188b. Not canonical CI, not a model strength or authenticity validator.

**Problem:** current `scripts/check_pr_evidence.py` correctly validates agent identity and strict complete receipt structure, but does not establish that a game's `git_sha` is in the candidate PR branch history. Receipt replay/stale-source mismatch can be missed by structure-only checks. This is an evidence-quality issue, not a claim that existing PRs fabricated games.

**Hypothesis/test:** require full, unshallowed git history and a `git merge-base --is-ancestor game_sha pr_head` relation; reject missing/unknown/future commit, malformed game, and shallow/unverifiable history. The test suite uses synthetic fixtures, never counterfeit match receipts. Such ancestry is necessary but does **not** prove real simulation, full model policy execution, no fallback, or correct game metrics; independent Actions logs remain required.

**Integration:** initial main `3a745c6f6a48c65528bcbeb81b8627b8db93f046`. Avoid editing shared `check_pr_evidence.py` or `ci.yml` while other agents integrate. Incorporation into shared PR gate would require separately reviewing existing PRs whose genuine receipts were recorded from a previous branch SHA or from unrelated workflow source histories, and enabling `checkout fetch-depth: 0`. Never block the existing pipeline without compatibility review.

**P2:** no new training or strategic improvement shown. Existing 1408-step V5 model remains unpromoted and has repeated rank-8 evidence. This audit is about trust in source-to-receipt version linkage, not performance.
