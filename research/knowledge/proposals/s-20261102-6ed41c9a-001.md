# Proposed P0/P1 improvement — durable Release resume as an explicit verified operation

Session: s-20261102-6ed41c9a, R001. Status: **PROPOSED; not yet accepted to curated knowledge**.

## Confirmed defect in existing main workflow
The scheduled training workflow restores from the most recent successful `v1-model` Actions artifact and persists a new `v1-model` artifact for only 90 days. Permanent model Releases exist elsewhere in the repository, but the shared main training entry point cannot explicitly restore these releases and does not publish a durable checkpoint after each successful completed game and held-out evaluation.

## Bounded corrective patch on own branch
Add opt-in `resume_release_tag` to main-only `train.yml`. A Release must match an immutable candidate in `models/registry.json`. Download both `model.zip` and `model.metadata.json`, verify SHA256 against the registry, archive CRC, optimizer file, pinned TavernGym contract and steps before invoking the existing `tavern_ai.train`. After a successful model-controlled full game and evaluation, publish an **unpromoted** GitHub Release and redownload/compare its bytes, then perform one local inference preflight. An empty tag preserves the prior Artifact path.

## Known constraints and gates
The script and workflow have not yet completed their own GitHub engine-backed proof at the time of writing; see session STATUS and actual workflow status. Neither the ability to reload a checkpoint nor a green unit-test run proves winning performance. A 1408-step unpromoted model recorded 0 purchases in 35 legally purchasable decision states on genuine seed 99128, despite complete game. Do **not** promote Best, start ranked games, or expand PPO simply because weights are durable.

Production Release creation adds `contents:write` permission to the main-only train workflow; scrutinize that before merge. Main CI must pass on the final merge commit. Other agents own overlapping draft registry/custody PRs and should not be overwritten.
