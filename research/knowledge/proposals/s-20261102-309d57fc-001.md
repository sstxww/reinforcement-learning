# V5 proposal: fail-closed checkpoint recovery and bounded release audit

**Evidence class:** inspected production source and five passing isolated Python tests; live TavernGym/PPO Action pending.

In main, train.py checks the engine metadata but not weight bytes before Torch load and writes the live checkpoint before companion metadata. Weekly train.yml primarily restores expiring Artifacts. Six GitHub Releases have published asset SHA256 digests, but listing assets is not independent load/resume verification.

Proposed fix: strict ZIP and metadata SHA256 checks, exact pinned engine check, staged checkpoint save and prior-pair backup, parent digest/step lineage, and an unpromoted candidate registry. A branch-only isolated Actions job downloads a specific durable V2 Release, verifies it, does only 128 PPO steps, demands a candidate-controlled complete eight-seat game, runs a two-seed paired descriptive evaluation, and creates a separate candidate prerelease only on full success.
