# V7 proposal: serial integration requires real central writer

Author session s-20261103-01cdbd04. Main base 990acd21d598a34a554a80c50089a8f1a9423ac4.

An expected PR head SHA protects against stale PR commits but not 10-20 separate agents concurrently writing main. Issue labels and comments are not atomic locks. Candidate solution: manual GitHub Actions workflow with fixed concurrency group autotavern-main-integrate, exact live SHA/ancestry and completed full-game CI, plus review attestation. A successful workflow is only a merged PR after the merge API returns a commit; main CI requires separate proof.

This PR is a proposal only. GitHub Actions job concurrency serializes jobs that actually enter this queue, not privileged API writes outside it. Stronger enforceable repo branch protection or native merge queue would be preferable. Never use such workflow to promote untested models, and never treat baseline infrastructure games as PPO success.
