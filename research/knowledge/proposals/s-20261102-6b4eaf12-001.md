# Proposal: safe Release registry and opportunity-conditioned rank-8 diagnosis

Provenance: independent V5 integration branch s-20261102-6b4eaf12, starting main f29a0a6e99161aca4163e51427f6bfabbe02f76f.

**Verified via API:** Six Release records exist; V1 and V2 release metadata include model.zip plus SHA256. Existing V1/V2 PR #9/#15 report valid PPO training and full games but no rank advantage. The current main does not contain a model registry.

**Proposed model lifecycle:** A Release entry begins Unverified even when asset digest is present. SHA256, saved engine/observation/action schema and ZIP+optimizer member checks are only offline preflight. Mark independent load/resume and model-controlled full game separately. Champion remains null until independent paired performance and restore gates pass.

**Observed behavior in PR #60 (not independently reproduced here):** three low-LR games, 36 actions, 21 natural end turns, zero buys, all rank 8; a higher-LR reference had many optional repeated actions and safety forced endings. Crucially, counts of legal buy opportunities were not reported. This is an association, NOT proof that learning rate alone caused rank 8.

**Next falsifiable diagnosis:** log each decision's legal action-family mask; current gold, board/hand size and turn; selected action family; zero-change streak; raw model end vs forced end. Compute BUY selection rate conditional on BUY availability, spend efficiency, early turn board counts and seat-paired rank distributions. Verify whether action IDs/observation layout match 1.1.0 before changing reward or scaling training. Preserve raw vs guarded performance as separate metrics.

**Merge gate:** independent full-game receipt, no secrets or large weights, all unit tests and latest-head CI green, main and other integrators checked again. Do not auto-promote policies or overwrite Champion.
