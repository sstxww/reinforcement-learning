# V7 proposal: pin PR readiness to the same exact SHA as CI

Scope: review-only, no model behavior claims. A PR's latest *head*, current *main*, a successful real full-game CI run **with nonempty successful jobs**, and a genuine same-session receipt must be verified together. A green older run, queued/action_required run with zero jobs, or a baseline-only receipt represented as model performance must not satisfy the gate.

Proof-of-concept: `scripts/v7_merge_gate_aadbbf93.py` plus mutation regressions in `tests/test_v7_merge_gate_aadbbf93.py`. These are code-level claims pending actual PR CI on this new change; no global consensus is implied.

Boundary: a read-only audit is **not** a lock. To safely merge under 10-20 concurrent sessions, deploy/enforce one serial GitHub Actions integration queue or a genuine CAS-protected lease and use GitHub PR merge with expected HEAD. Until then, no automated merge authorization is claimed. Existing #179 is a related independent stacked-PR audit; avoid duplicating its changes.
