# V1 故障自修复与持续训练闭环（独立 ChatGPT 会话）

> 本协议中的 Agent = 用户分别开启的一个 ChatGPT 会话，**不是子 Agent**。每个会话只负责自己的分支、运行任务、研究记录和恢复计划。

## 核心原则

**继续训练不等于忽略失败。** 一轮的状态机为：

```text
SYNC(main + 已验证经验) → CLAIM(唯一 Session ID / 独立分支 / 假设)
 → BASELINE(现有策略与评测) → CHANGE(最小可复现变更)
 → TEST(单测/静态检查) → TRAIN(有界预算)
 → REAL_GAME(模型/候选策略亲自跑完八人 TavernGym)
 → EVAL(独立种子，比较基线)
 → SAVE(模型+哈希+精简实验日志+真实收据)
 → PR(审查/CI) → LEARN(读新合并经验，进入下一轮)
```

任一步失败进入 `DIAGNOSE → FIX → RETEST`，**不能跳过失败门槛直接晋升候选或声称比赛成功**。若连续两次有根因的修复后仍不能通过，标记 `blocked`，保存完整精简证据，隔离失败候选，下一轮改用安全可运行的基线/另一假设；不在同一个错误上无限消耗 Actions 分钟。

## 真实失败样本（2026-11-02 检查）

1. **模型完整对局卡死**：有 256 步 PPO 检查点可以加载推理，但模型控制的完整对局触发 `Full-game safety limit exceeded`。这是策略进展/循环控制问题，不等于训练成功。先记录连续动作、回合、同一状态重复次数；修正策略的无进展动作循环、结束回合条件或训练采样方式，然后再次由**候选模型自身**完成完整八人游戏。可以使用规则基线救援验证基础设施，但**救援对局不得冒充纯候选模型的战绩**。
2. **持久化 403**：发布 GitHub Release 时出现 `HTTP 403 Resource not accessible by integration`。先核对工作流 token 权限、仓库设置和任务运行上下文。**不要无限重试相同 403，也不要把密钥写进日志**。如果权限暂时不可调整，保留版本化 Artifact、模型哈希、训练参数和临时恢复步骤，并标注 `persistent_checkpoint=false`；不得宣称长期断点续训已解决。需要更高权限时报告真实阻塞给用户，不擅自改变仓库安全设置。
3. **算法测试断言失败**：站位策略曾在相同手牌测试中预期动作 55、实际 61。先复核动作编码：46–125 是 `hand * 8 + position + 46`。从模型行为、业务期望和测试错误三种可能性分析，增加最小回归用例；不能单纯删掉失败断言。
4. **大量重复运行**：数分钟内出现大量 CI/实验任务失败、取消、重复提交。不要将 push/工作流互相触发成无界循环。一个会话对同一失败假设最多进行**首次运行 + 两轮有实质修改的重试**；稳定提交 SHA 不重复启动同一确定性失败测试。私有实验工作流使用自己的 concurrency group、有限 timeout、固定的实验数与训练步数，避免生成 commit → push → workflow → 自动 commit 的环。**不取消、不修改其他会话的任务。**
5. **`action_required` / 无 job**：不等于程序错误。检查仓库审批、工作流策略、权限和触发上下文；在有证据前标记为运行受阻，不能声称模型/CI 测试失败或成功。

这些是具体的诊断入口，不预先规定修复实现；研究会话要自己读最新日志和代码，验证根因。成功的旧 CI 不能替代最新 commit 的 CI。

## 自动修复决策树

- **依赖/网络暂态失败**：有界退避重试一次；若复现，固定依赖和校验下载数据后重新构建。
- **Python/Rust 测试失败**：复现最小用例 → 定位代码与测试假设 → 最小修复 + 回归测试 → 重新跑全部相关门槛。
- **训练数值异常/显存或 CPU 超限**：先恢复上一个可靠 checkpoint、减小 batch/并行/训练步数并记录参数变化；不能悄悄复用不兼容的权重。
- **模型对局超限/非法动作**：保存诊断序列与种子，修正策略/结束条件/掩码使用，重新完整打完一局；纯模型的胜率指标不能混入 fallback 策略的局。
- **GitHub 403/审批/不可用权限**：停止权限类盲目重试，保留替代证据，必要时报告明确的人工授权阻塞。
- **评测无提升**：不得晋升 Best；保留精简失败经验，重新选择优化假设，而不是重复增加同一组训练步数。

任何修复都记录：`failure_signature`、原始 run/job URL、复现 seed、根因证据、代码改动、修复后 run URL、最终状态。用真实的成功运行确认已解决，不以“理论上应该”收尾。

## 每次实验必须保存的证据

```text
research/sessions/<SESSION_ID>/STATUS.md
research/sessions/<SESSION_ID>/round-<NNN>.md
research/sessions/<SESSION_ID>/failures/<NNN>-<failure-slug>.md
research/knowledge/proposals/<SESSION_ID>-<NNN>.md
experiments/<SESSION_ID>/<NNN>-<seed>.json
```

每份报告应包括：main 基线 commit SHA、自己的分支和 commit、环境 commit/hash、观测/动作 layout、实验配置和随机种子、训练步数、训练运行 URL、完整对局收据、独立评测指标和样本量、模型位置/哈希/过期策略、故障记录、下一轮决策。

未完成的游戏不能伪造 JSON 收据。若策略故障导致没有完整比赛，改用**不同文件名**记录失败事件，而不是写 `completed:true`。不要把完整游戏存档、原始权重或大量 rollout 提交 Git。

## 并发限制与集成

- 每个会话启动先生成唯一 `SESSION_ID`，检查开放 PR 和其他会话的已提交研究记录。
- 独立分支 `agent/<SESSION_ID>/optimization-<NNN>`、自己独占的日志和模型命名空间。禁止直接写 main、他人分支、公共知识索引、他人 Artifact 和其他会话训练工作流。
- 现有主分支 `.github/workflows/train.yml` 有 main-only 限制和共享 concurrency；不要用它给多会话同时训练。每个会话可在自己分支配置独立有限工作流，真正通过 GitHub Actions 执行，不能宣称 ChatGPT 会话结束后仍在执行模型推理。
- 经验证的改动以 PR 提交；只有集成者合并到 main 后才成为正式共享知识。未合并 PR 的结论可作为未验证线索。
- 正式 TavernArena 计分对局未经用户单独授权不得启动。

## 完成定义

一轮只有在**候选策略或模型自己跑完真实八人对局**、回归测试与最新 CI 通过、独立评测样本量如实披露、持久化状态准确、故障处理与经验文档都提交到自己的分支且 PR 已创建后，才可标记 `completed_for_review`。合并与否由集成者决定。

如果本轮被阻塞，状态为 `blocked_with_evidence`；同一会话应按新假设继续**能安全执行的**实验，直到资源预算达到上限，不要无限运行，不要假报成功。

**注意**：GitHub Actions 能按预配置运行，但它本身不会自动生成修复代码。故障判断和改代码只能由当前有执行能力的 ChatGPT 会话或另一个明确配置的自动编码执行器完成。
